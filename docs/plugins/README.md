# Плагины Dev Hangar

Плагин — это папка с файлами `plugin.json` и `main.js`, которая добавляет в Hangar что-то своё:

- **поддержку нового стека**: Hangar начинает распознавать проекты, показывать бейдж, ставить ваши команды
  на кнопки Dev и Build и выводить зависимости;
- **вкладку в проекте** с любым интерфейсом;
- **свой экран** в боковой панели, не привязанный к проекту;
- **кнопку** в шапке проекта или **команду** в меню;
- реакцию на **события**: открыт проект, закончилась сборка и т. п.

- **Справочник API:** [API.md](API.md)
- **Типы для автодополнения:** [`src/plugins/hangar.d.ts`](../../src/plugins/hangar.d.ts)
- **Примеры:** [`examples/plugins/`](../../examples/plugins)

## Быстрый старт за 2 минуты

1. Откройте **Плагины** в нижней части боковой панели.
2. Нажмите **«Создать плагин»**, введите название, например «Мои заметки», и нажмите **«Создать»**.
3. Hangar создаст папку с шаблоном, включит плагин и откроет его в вашем редакторе.
4. Откройте любой проект: у него появилась новая вкладка, а в меню **▾ (Все команды)** — пункт «Поздороваться».
5. Поменяйте текст в `main.js`, сохраните файл и нажмите **⟳ (Перезагрузить)** у плагина на экране «Плагины».

Шаблон уже рабочий, дальше остаётся его менять под себя.

## Где лежат плагины

```
%APPDATA%\com.bolat.devhangar\plugins\<id плагина>\
```

Точный путь можно открыть кнопкой **«Папка плагинов»**. Каждый плагин хранится в отдельной папке, и её имя
должно совпадать с полем `id` в `plugin.json`.

## Структура плагина

```
my-notes/
├─ plugin.json     ← манифест (обязателен)
├─ main.js         ← код: ES-модуль с функцией activate (обязателен)
├─ style.css       ← стили (необязательно, указывается в "style")
├─ hangar.d.ts     ← типы API для автодополнения (кладётся шаблоном)
├─ README.md
└─ icon.png …      ← любые свои файлы: hangar.plugin.readFile / assetUrl
```

## plugin.json

```json
{
  "id": "my-notes",
  "name": "Мои заметки",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "Заметки по проекту прямо в Hangar",
  "author": "Имя или @github",
  "homepage": "https://github.com/you/hangar-my-notes",
  "minAppVersion": "0.7.0",
  "main": "main.js",
  "style": "style.css",
  "icon": "note",
  "permissions": ["fs:read"],
  "settings": [
    { "key": "fileName", "label": "Файл заметок", "type": "string", "default": "NOTES.md" }
  ]
}
```

| Поле | Обяз. | Описание |
|---|:-:|---|
| `id` | ✔ | Уникальный id: `a-z`, `0-9`, `-`, `_`, `.`, от 2 до 64 символов. **Совпадает с именем папки.** |
| `name` | ✔ | Название, которое видит пользователь. |
| `version` | ✔ | Версия плагина в формате semver: `1.0.0`. |
| `apiVersion` | ✔ | Версия Plugin API. Сейчас это `1`. |
| `description` | | Одна-две фразы о том, что делает плагин. |
| `author`, `homepage` | | Автор и ссылка на репозиторий или страницу. |
| `minAppVersion` | | Минимальная версия Dev Hangar. На более старой версии плагин не включится. |
| `main` | | Файл с кодом, по умолчанию `main.js`. |
| `style` | | CSS-файл. Подключается, пока плагин включён. |
| `icon` | | Иконка из набора Hangar (список возвращает `hangar.ui.icons()`). |
| `permissions` | | Нужные плагину [разрешения](#разрешения). |
| `settings` | | [Настройки](#настройки-плагина), которые пользователь меняет на экране «Плагины». |

## main.js и жизненный цикл

`main.js` — это ES-модуль. Он должен экспортировать функцию `activate`, а `deactivate` экспортировать
необязательно:

```js
/** @param {import("./hangar").Hangar} hangar */
export function activate(hangar) {
  // регистрируем вкладки, команды, подписки
}

export function deactivate() {
  // необязательно: освободить то, что не зарегистрировано через hangar.*
}
```

Как это работает:

1. При запуске Hangar читает папку плагинов и проверяет `plugin.json` каждого плагина.
2. Для каждого **включённого** плагина подключается `style` (если он указан), загружается `main`
   и вызывается `activate(hangar)`. У каждого плагина свой объект `hangar`.
3. Когда плагин выключают, перезагружают или удаляют, вызывается `deactivate()`. После этого Hangar
   **сам** убирает всё, что плагин зарегистрировал через `hangar.*`: вкладки, команды, подписки на события
   и колбэки `onDispose`.

> Если вы заводите таймер `setInterval` или вешаете обработчик на `window`, уберите его в
> `hangar.onDispose(() => …)`, иначе после перезагрузки плагина он останется висеть.

Если `activate` выбрасывает исключение, плагин получает статус **«ошибка»**, и текст ошибки
показывается на экране «Плагины». Остальная часть приложения продолжает работать.

## Что может плагин

### Новый стек

Это самый «глубокий» способ расширить Hangar. Зарегистрированный стек ведёт себя так же, как встроенный:

- в шапке проекта, на «Обзоре» и в боковой панели появляется **бейдж**;
- команды с `kind: "dev"` и `"build"` попадают на **кнопки Dev и Build**, остальные — в меню «Все команды»;
- зависимости показываются на вкладке **«Зависимости»**;
- «Найти проекты в папке…» **находит** такие проекты;
- `when` у вкладок и команд видит id стека в `project.stacks`.

```js
hangar.stacks.register({
  id: "hugo",
  label: "Hugo",
  color: "#ff4088",

  // корень проекта или подпапка монорепы — это решает Hangar, вы только отвечаете «да / нет»
  async detect(ctx) {
    return (await ctx.has("hugo.toml")) || (await ctx.has("hugo.yaml"));
  },

  actions(ctx) {
    return [
      { id: "server", label: "hugo server", command: "hugo server -D", kind: "dev", primary: true },
      { id: "build",  label: "hugo --minify", command: "hugo --minify", kind: "build" },
      { id: "new",    label: "Новый пост", command: "hugo new content posts/new.md" },
    ];
  },

  async dependencies(ctx) {
    const cfg = await ctx.readText("hugo.toml");
    const theme = cfg?.match(/theme\s*=\s*"([^"]+)"/)?.[1];
    return theme ? [{ name: theme, version: "theme" }] : [];
  },
});
```

Как это работает:

1. Сначала проект анализирует Hangar: определяет встроенные стеки и находит подпроекты.
2. Затем для **корня** и каждой **подпапки-кандидата** (папки первого уровня, а также `apps/*`, `packages/*`,
   `services/*`, `libs/*`, кроме скрытых и `node_modules`, `target`, `dist`…) вызывается `detect(ctx)`
   каждого зарегистрированного стека. Если в подпапках искать не нужно, укажите `subdirs: false`.
3. Если `detect` вернул `true`, папка получает бейдж, команды из `actions(ctx)` и зависимости из
   `dependencies(ctx)`. Подпапка, которую Hangar сам не распознал, становится отдельным модулем монорепы.

Что есть в `ctx`:

| | |
|---|---|
| `ctx.has("file")` | Есть ли файл или папка (путь относительно проверяемой папки, можно `"src/main.ts"`). |
| `ctx.readText("file")` / `ctx.readJson("file")` | Содержимое файла или `null`, если его нет. |
| `ctx.list()` | Содержимое папки. |
| `ctx.stacks` | Что Hangar уже нашёл в этой папке (например, `["node", "vite"]`). |
| `ctx.isRoot`, `ctx.relPath`, `ctx.dir`, `ctx.projectPath` | Где мы находимся. |

Детектор читает файлы **только внутри проекта** (`..` и абсолютные пути запрещены), поэтому разрешение
`fs:read` для этого не нужно.

Советы:

- **`detect` должен быть быстрым.** Он вызывается для каждой папки каждого проекта. Если проверяете
  несколько файлов, один раз вызовите `ctx.list()` (результат кэшируется) и ищите имена в нём, а не
  делайте много `ctx.has(...)`. Читайте файлы, только когда без этого не обойтись.
- **Будьте строги.** `config.toml` есть у многих инструментов, поэтому проверяйте сочетание признаков.
  Ложное срабатывание повесит ваш бейдж на чужие проекты.
- **`primary: true`.** По умолчанию кнопка Dev берёт первую найденную dev-команду. Если в проекте
  есть и `package.json`, а главная команда — ваша, поставьте `primary: true`.
- `cwd` у команды задаётся относительно проверяемой папки.
- Если команды зависят от настроек плагина, вызывайте `hangar.stacks.refresh()` в `settings.onChange`.

Полный пример лежит в [`examples/plugins/hugo-stack`](../../examples/plugins/hugo-stack).

### Свой экран

Экран появляется отдельной строкой в боковой панели, над кнопками «Диск» и «Плагины», и занимает
всю правую часть окна. Он подходит для того, что не относится к одному проекту: сводки, дашборда,
трекера задач.

```js
hangar.pages.register({
  id: "dashboard",
  label: "Сводка",
  icon: "layers",
  mount(el, { signal }) {
    el.innerHTML = `<div style="padding:20px"><h1>Все проекты</h1>…</div>`;
    return () => { /* очистка */ };
  },
});
```

Открыть свой экран из кода можно через `hangar.ui.showPage("dashboard")`. Пример лежит в
[`examples/plugins/projects-dashboard`](../../examples/plugins/projects-dashboard).

### Вкладка в проекте

```js
hangar.tabs.register({
  id: "notes",
  label: "Заметки",
  icon: "note",
  when: (project) => project.isGit,          // необязательно: для каких проектов показывать вкладку
  mount(el, { project, signal }) {
    el.innerHTML = `<div style="padding:20px">Проект: ${hangar.util.escapeHtml(project.name)}</div>`;
    return () => { /* очистка при закрытии вкладки */ };
  },
});
```

`mount` вызывается каждый раз, когда пользователь открывает вкладку. `el` — пустой элемент, и вся
отрисовка внутри него лежит на вас. `signal` (AbortSignal) срабатывает, когда вкладку закрыли. Его
удобно передавать в `fetch` и проверять после долгих `await`.

### Команда или кнопка

```js
hangar.actions.register({
  id: "deploy",
  label: "Деплой",
  icon: "upload",
  toolbar: true,                // true — кнопка в шапке проекта; без него — пункт в меню ▾
  when: (p) => p.stacks.includes("vue"),
  async run(project) {
    await hangar.shell.run(project.path, "npm run deploy", { label: "Деплой" });
  },
});
```

### События

```js
hangar.events.on("process:exit", (e) => {
  if (e.kind === "build" && e.code !== 0) hangar.ui.toast(`Сборка ${e.label} упала`, "error");
});
```

Доступные события: `project:open`, `process:start`, `process:exit`, `theme:change`.
Их данные описаны в [API.md](API.md#events).

### Хранилище

```js
const count = hangar.storage.get("launches", 0);
hangar.storage.set("launches", count + 1);
```

Хранилище принимает любые JSON-значения. Они сохраняются в конфиг Hangar отдельно для каждого плагина
и удаляются вместе с плагином. Разрешение для него не нужно.

### Всё остальное

Работа с файлами (`hangar.fs`), git (`hangar.git`), командами (`hangar.shell`), проектами
(`hangar.projects`) и UI-хелперами (`hangar.ui`) описана в справочнике **[API.md](API.md)**.

## Разрешения

Часть API работает только с разрешением, указанным в `permissions`. Если плагин вызывает метод без
нужного разрешения, получает понятную ошибку:
`плагину нужно разрешение "fs:read" в plugin.json → "permissions"`.

| Разрешение | Что открывает |
|---|---|
| `projects:read` | `hangar.projects.*`: список проектов, стек, зависимости, git-статус |
| `fs:read` | `hangar.fs.readText / listDir / exists / searchFiles / searchText` |
| `fs:write` | `hangar.fs.writeText` |
| `git:read` | `hangar.git.*`: история, коммиты, diff |
| `shell` | `hangar.shell.exec / run`: запуск команд |

Без разрешений доступны `tabs`, `actions`, `events`, `storage`, `settings`, `ui`, `util`, `vue`
и `plugin`. Кроме того, во вкладки и команды всегда передаётся `project` (путь, имя, стек).

Перед включением чужого плагина Hangar показывает пользователю список запрошенных разрешений.
**Просите только то, что действительно нужно.**

## Настройки плагина

Опишите настройки в `plugin.json`, и Hangar сам нарисует для них форму на экране «Плагины»:

```json
"settings": [
  { "key": "token",   "label": "API-токен", "type": "string", "placeholder": "ghp_…" },
  { "key": "limit",   "label": "Сколько показывать", "type": "number", "default": 20 },
  { "key": "compact", "label": "Компактный вид", "type": "boolean", "default": false },
  { "key": "mode",    "label": "Режим", "type": "select", "default": "all",
    "options": [{ "value": "all", "label": "Все" }, { "value": "mine", "label": "Только мои" }] },
  { "key": "template","label": "Шаблон", "type": "text", "description": "Многострочный текст" }
]
```

Чтение значений:

```js
const limit = hangar.settings.get("limit");          // значение пользователя или default
hangar.settings.onChange((key, value) => rerender());
```

## Интерфейс: HTML, стили, Vue

### Готовые классы и переменные Hangar

Используйте классы приложения, и плагин будет выглядеть как часть Hangar:

| Класс | Что это |
|---|---|
| `btn`, `btn primary`, `btn ghost`, `btn sm`, `btn danger`, `btn success` | кнопки |
| `input` | поле ввода, select, textarea |
| `card`, `card-h`, `card-b` | карточка, её заголовок и тело |
| `badge`, `badge green / red / yellow / blue` | метки |
| `muted`, `dim`, `mono`, `row`, `grow`, `ellipsis`, `spacer` | утилиты |
| `md` | оформление отрисованного Markdown |

Цвета берите **только из CSS-переменных**. Тогда плагин корректно выглядит и в светлой, и в тёмной теме:

```
--bg  --bg-2  --panel  --panel-2  --hover  --border  --border-2
--text  --text-2  --text-3  --accent  --accent-soft
--green  --green-soft  --red  --red-soft  --yellow  --yellow-soft  --purple
--radius  --mono  --sans
```

Иконки: `hangar.ui.icon("check", 16)` возвращает SVG-строку.

### Свой CSS

Укажите `"style": "style.css"` и **начинайте все классы с префикса плагина** (`.npo-table`, а не
`.table`). Стили плагина действуют на всё приложение, и без префикса можно случайно сломать чужую вёрстку.

### Безопасный HTML

Любые данные из файлов, git или от пользователя прогоняйте через `hangar.util.escapeHtml(...)` перед
вставкой в `innerHTML`.

### Vue

Hangar отдаёт плагину свой экземпляр Vue 3 через `hangar.vue`, поэтому собирать Vue в бандл не нужно.
Компилятора шаблонов в нём нет, так что вместо шаблонов используйте `h()`:

```js
const { createApp, h, ref } = hangar.vue;

hangar.tabs.register({
  id: "counter",
  label: "Счётчик",
  mount(el) {
    const app = createApp({
      setup() {
        const n = ref(0);
        return () => h("button", { class: "btn", onClick: () => n.value++ }, `Нажато: ${n.value}`);
      },
    });
    app.mount(el);
    return () => app.unmount();
  },
});
```

Полный пример лежит в [`examples/plugins/release-checklist`](../../examples/plugins/release-checklist).

## Отладка

- **Ошибки загрузки** показываются красным на карточке плагина на экране «Плагины».
- **Ошибки в `run`, обработчиках событий и `mount`** выводятся во всплывающем уведомлении
  и в консоли DevTools с префиксом `[plugin <id>]`.
- **DevTools.** Запустите Hangar из исходников (`npm run tauri dev`), затем нажмите правой кнопкой
  → *Inspect*. Код плагина виден в разделе Sources как `hangar-plugin://<id>/main.js`, и в нём можно
  ставить точки останова.
- **Перезагрузка.** После правки кода нажмите ⟳ у плагина или «Перезагрузить все». Перезапускать
  приложение не нужно.

## Несколько файлов и npm-пакеты

`main.js` загружается как **один** ES-модуль. Поэтому:

- относительные импорты (`import x from "./utils.js"`) **не работают**;
- голые импорты (`import dayjs from "dayjs"`) **не работают**;
- импорт по полному URL (`await import("https://esm.sh/dayjs@1.11.13")`) работает, но тогда
  плагину нужен интернет.

Если плагин вырос до нескольких файлов или зависит от npm-пакетов, соберите его в один файл,
например через esbuild:

```bash
npm i -D esbuild
npx esbuild src/index.ts --bundle --format=esm --target=es2022 --outfile=main.js
```

Если пишете на TypeScript, подключите типы из `hangar.d.ts`:

```ts
import type { Hangar } from "./hangar";
export function activate(hangar: Hangar) { … }
```

Нетекстовые файлы (картинки и т. п.) кладите рядом и получайте через `await hangar.plugin.assetUrl("icon.png")`,
а текстовые — через `await hangar.plugin.readFile("data.json")`.

## Как поделиться плагином

1. Выложите папку плагина в репозиторий на GitHub или отправьте её архивом.
2. Получатель распаковывает её куда угодно и на экране «Плагины» нажимает **«Установить из папки…»**.
   Hangar скопирует плагин к себе (папки `node_modules` и `.git` пропускаются) и спросит, включать ли его.
3. **Обновление** делается так же: «Установить из папки…» с новой версией заменяет старую. Включённость,
   настройки и данные из `storage` при этом сохраняются.

Чек-лист перед публикацией:

- [ ] `id` уникален и совпадает с именем папки
- [ ] `version` поднята, а `minAppVersion` указана, если вы используете новые возможности API
- [ ] в `permissions` только то, что действительно используется
- [ ] в README описано, что делает плагин и зачем ему каждое разрешение

## Безопасность

Плагины работают **внутри приложения**, как расширения VS Code. Разрешения ограничивают API `hangar.*`
и показываются пользователю, но **песочницей не являются**: JavaScript плагина выполняется в том же окне,
что и Hangar. Поэтому:

- устанавливайте только плагины, которым доверяете, и читайте их код;
- новые плагины, установленные из папки, по умолчанию **выключены**. При включении Hangar показывает
  список запрошенных разрешений;
- плагин, созданный кнопкой «Создать плагин», включается сразу, потому что вы его автор.

## Версии API

- Текущая версия Plugin API: **1** (`hangar.apiVersion`).
- В рамках одной версии API меняется только **без поломок**: новые методы и поля добавляются,
  старые сохраняются.
- Ломающие изменения повышают `apiVersion`. Плагин с `apiVersion` выше, чем у установленного
  Hangar, не загрузится и попросит обновить приложение.
- Если плагину нужна возможность, которая появилась в конкретной версии Hangar, укажите `minAppVersion`.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| «"id" должен совпадать с именем папки» | Переименуйте папку или поменяйте `id`. |
| «main.js должен экспортировать функцию activate» | Нужен именованный экспорт `export function activate(...)`, а не `export default` или `module.exports`. |
| `Failed to resolve module specifier` | В коде есть `import` из npm или из соседнего файла. Соберите плагин в один файл ([подробнее](#несколько-файлов-и-npm-пакеты)). |
| «плагину нужно разрешение …» | Добавьте разрешение в `permissions`, затем выключите и снова включите плагин. |
| Вкладка не появилась | Проверьте условие `when`, статус плагина и то, что `tabs.register` вызывается внутри `activate`. |
| Стек не определяется | Проверьте `detect` в DevTools: ошибки пишутся в консоль как `[plugin <id>] stack "…" detect() failed`. Пути в `ctx.has` указываются относительно проверяемой папки. |
| Кнопка Dev запускает не мою команду | В проекте уже есть dev-команда (например, из `package.json`). Добавьте своей команде `primary: true`. |
| После перезагрузки что-то срабатывает дважды | Не снят таймер или обработчик, оберните его в `hangar.onDispose`. |
| Стили «поехали» во всём приложении | Классы плагина без префикса перекрывают классы Hangar. |
