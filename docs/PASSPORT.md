# Паспорт проекта

Паспорт — это описание, статус, задачи, роадмап и документация проекта, которые лежат **в самом
репозитории** обычными markdown-файлами. Dev Hangar показывает их на вкладке «Паспорт» и на карточках
сетки, а ИИ-агенты (Claude Code, Cursor, Codex, Copilot…) читают и обновляют те же файлы:
берут задачи, отмечают сделанное, пишут, на чём остановились.

Почему файлы, а не база в приложении:

- паспорт живёт в git вместе с кодом и переезжает вместе с проектом;
- любой агент понимает markdown без интеграций и API;
- если Dev Hangar не нужен — файлы остаются полезными сами по себе.

## Как начать

1. Откройте проект → вкладка **«Паспорт»** → «Создать паспорт».
   Hangar создаст `.hangar/` и (по галочкам) допишет в `CLAUDE.md` / `AGENTS.md` блок «читай `.hangar/`».
2. Промпт «заполни паспорт по коду» окажется в буфере обмена — вставьте его в своего агента.
3. Дальше работайте как обычно: Hangar перечитывает паспорт, когда вы возвращаетесь в окно.

## Формат `.hangar/` (hangar/1)

| Файл | Что внутри |
|---|---|
| `project.md` | Описание проекта, статус, раздел «Сейчас» |
| `tasks.md` | Задачи, сгруппированные по разделам (колонки доски) |
| `roadmap.md` | Версии / этапы и их цели |
| `docs/` | Документация: архитектура, решения, инструкции (любые `.md`) |
| `README.md` | Описание формата и правила для ИИ-агента |

### project.md

```markdown
---
format: hangar/1
name: Название
status: active        # idea | active | paused | done | archived
summary: Одна строка — что это за проект
tags: web, vue, tauri
---

# Название

## Описание
Для кого проект, что умеет, как устроен.

## Сейчас
Что в работе и на чём остановились.
```

Статус понимается и по-русски: `идея`, `в работе`, `на паузе`, `готов`, `архив`.
Разделы с другими заголовками показываются как часть описания.

### tasks.md

```markdown
# Задачи

## В работе
- [ ] Сворачивание сайдбара #ui !high
  Подробности — строками с отступом под задачей.

## Очередь
- [ ] Экспорт в PDF

## Готово
- [x] Сетка проектов #ui
```

- Каждый заголовок `##` — колонка доски, названия любые. Колонки «В работе» и «Готово»
  (или `In progress` / `Done`) Hangar узнаёт: отметка задачи переносит её в «Готово».
- `#тег` — теги, `!high` / `!low` (или `!важно` / `!потом`) — приоритет.
- Строки с отступом под задачей — её описание; вложенные чекбоксы тоже попадают туда.

### roadmap.md

```markdown
# Роадмап

## 0.9.0 — Режим ИИ `в работе`
Пара строк о цели версии.
- [x] Формат паспорта
- [ ] Вкладка в приложении

## 1.0.0 `план`
```

Статус этапа — в обратных кавычках в конце заголовка: `план` / `в работе` / `готово`
(`planned` / `active` / `done`), либо ✅ / 🚧. Без статуса этап считается готовым, если все его пункты отмечены.

## ИИ-агенты

- **Любой агент:** у каждой задачи есть кнопка «скопировать промпт» — «возьми эту задачу, отметь её, обнови „Сейчас“».
- **Claude Code:** встроенный плагин (экран «Плагины» → «Установить»). Кнопка «Claude» в шапке проекта
  и у каждой задачи; задачу можно выполнить интерактивно в терминале или без вопросов в консоли Hangar.

## Свой формат

Если у вас уже есть своя структура, Hangar не заставляет переезжать: плагин может зарегистрировать
свой формат через `hangar.passport.registerFormat` — см. [Plugin API](plugins/API.md#passport).
